# 1 从软件1.0到软件3.0

人们编写软件的方式不断在变化，从最早计算机诞生开始，到最近ChatGPT的出现。

**从演化的角度看**

1. 软件1.0（编程语言）编写了软件2.0的算法逻辑；

2. 软件2.0（机器学习）对自然语言的理解产生了软件3.0；

3. 软件3.0（prompt）又能用来编写软件1.0的代码；

4. 软件1.0和软件3.0结合产生软件3.5(编程语言 + prompt)；

5. 软件3.5将可以编写软件3.5；

**从使用难度的角度看**

1. 软件1.0需要会写代码的程序员；

2. 软件2.0需要有数据有算力的公司；

3. 软件3.0只需会打字的普通人；

4. 由于软件3.0可以编写软件1.0，意味着普通人也将能够间接编写软件1.0，甚至编写软件3.5。

## 1.1 软件1.0

软件1.0的出现，让人们可以使用编程语言，如Python、Javascript等，去编写满足各种需求的软件，今天我们手机或电脑里用的产品几乎都是软件1.0的产物。

在这个阶段，程序员需要使用精确、严谨、有逻辑的语言去编写软件的逻辑或页面，一旦没有按照指定的规则编写，可能只是多打了一个逗号，程序便会跑不通。

下面是一个简单的示例（可跳过）

```python
number = input("请输入一个整数：")

if number % 2 == 0:
    print(number, "是偶数")
else:
    print(number, "是奇数")
```

一个复杂的软件，常常要面对许多数据，以及会遇到各种情况，为了高效地应对这些困难，程序中会包含很多条件判断和循环的结构，可以根据不同的情况执行不同的代码。

不过这还不够，程序中还需要对一些经常遇到问题进行抽象，写成函数或对象，当再次遇到相同的问题时，便可以使用之前编写的函数了，不用重新造轮子。

这些复杂的逻辑，也使得编程存在着门槛，若要编写一个完整的软件或网页，需要学习很多知识，还需要进行很多的练习，因此普通人难以利用编程去解决自己的问题。

软件1.0具有很强的通用性，但它并不能解决所有的问题，例如它难以处理自然语言或是识别图像，这是因为处理这类问题时，遇到的场景实在是太多了，无法为每个场景都写一个逻辑。因此，便出现了软件2.0。

## 1.2 软件2.0

相比于软件1.0，需要把逻辑直接、明确、显性的写出来，软件2.0则不直接写明逻辑，而是让机器自己学会如何处理各种各样的场景，逻辑是隐性的，就像一个人即便不知道母语中的语法，也能够使用母语进行灵活地交流。

为了让机器学会这些本领，我们也需要使用到软件1.0的编程语言，让机器进行学习是需要方法的，而这个方法的逻辑是显性的，例如模仿人类大脑的神经网络算法，便是用软件1.0写的。

只有算法是不够，软件2.0还要求有很多数据，机器会从海量的数据中进行学习，除了数据，对机器进行训练还需要有很多算力。

因此，软件2.0的门槛比软件1.0的门槛还高，通常只有那些既有数据又有钱的公司才能搞，只有程序员是不够的，这和普通人更没有什么关系。

不过，一旦训练好了机器，其能做到的事情是惊人的，例如AI绘画和ChatGPT的出现，从此人们可以让机器仅仅根据文字就生成惊艳图像，也可以让机器完成很多文字工作，这也产生了所谓软件3.0。

## 1.3 软件3.0

ChatGPT的出现，让人们发现，原来机器对语言的理解可以到达非常高的地步（当然，机器只是表面看起来理解了，实际上只是在做文本预测），它似乎能听懂你说的任何话，甚至有些时候看起来比人类的理解能力还强。

有了这个能力，机器便可以帮助人类完成很多原来无法通过软件1.0实现的任务。

对机器的指令或提问称为prompt，prompt有好坏之分，好的prompt可以让我们得到所要的结果，甚至超出自己的预期。

在AI绘画方面，有时仅仅加上一个词（magic word），结果便会很不一样，好的prompt甚至可以产生接近艺术的作品。

通过设计prompt，让AI得到一个预期的结果，可以认为是在用自然语言进行编程，在网络上也被叫做软件3.0（下图）。
![](https://files.mdnice.com/user/40454/8044ed17-fa31-4df8-9aa6-91a54f2a6e38.jpg)

软件3.0的将「编程」的难度大大降低，只要会打字，便可以编程，这和软件1.0和软件2.0有着巨大的差别，意味着技术可以触达更多的人了。

相比于AI绘画对prompt过于敏感，在处理简单任务时ChatGPT则好得多，例如要让它翻译文字，你可以说“翻译一下这句话”，或是“translate to Chinese”，或是”翻译”，得到的结果不会有太多不同。

不过如果是复杂的任务，不同的prompt写法，效果可能就会有差异了，然而由于ChatGPT不是一个确定性的系统，我们不能给出一套系统的理论出来，让我们可以预测什么样的prompt会产生好的结果，更多的时候得依靠经验和反复的尝试 。

不过，也并不是完全靠运气。有一些已知的问题，比如回答没有逻辑，或结果不是我们想要的，对于此类问题，人们发现了一些方法来和ChatGPT进行更好的交流，如给ChatGPT一些示例，让它能够举一反三，或是教它要一步步推理，不要太快给出答案。

具体可以见 [从简单的提问到类比](https://www.notion.so/028f593862f1422fac5e8df97d27cb4e) 和 [增强ChatGPT回答的逻辑性](https://www.notion.so/ChatGPT-87036720bbed4d55846ab9ccdc04b359) 这两篇文章。对于如何写好prompt，理解这两篇文章就够了，要进一步利用好ChatGPT，最重要的是自己体验，以及prompt之外的功夫，功夫在诗外这句话在这里也是适用的。

如果只是简单的使用ChatGPT，比如做一下翻译、总结文章、生成故事，甚至是写软件1.0的代码，把这些任务视作「编程」，虽然听起来有点不合适，但其实还有有些道理的，因为都是要通过写「指令」让机器帮助人类完成某一项特定任务。只是用自然语言作为指令，似乎是很简单的事，不过由于自然语言非常的通用，其实是可以编写出很复杂的prompt的，来解决更加个性化的需求。

下面举一个的例子，示范一下，用自然语言编程可能会是什么样的。

### 1.3.1 辅助英语阅读

假设我们在阅读一篇英语文章，如何使用ChatGPT帮助我们阅读呢？

首先，我们可能会要求ChatGPT对阅读的段落进行翻译，但有时为了练习英文阅读，或是认为翻译会改变原意，不想把整个段落全部翻译成中文，只要求对某些生僻的单词或术语进行翻译即可。于是我们可以写这么一个prompt，定义一个规则 A，规则 A只会对部分的单词进行翻译，如下图。

![](https://files.mdnice.com/user/40454/65830691-47d5-48a9-a652-f635153faf2f.png)

有时候，我们想要提高段落的可读性，把专业术语圈出来，例如，我们想要把“foundation models”（基础模型），这个词标记出来，让它变得更明显。这时我们的prompt可以定义一个新的规则 B，规则 B会在“foundation models”这个词组的前面加上一个emoji🤖️，如下图。


![](https://files.mdnice.com/user/40454/678cf231-26df-4a2c-946d-429eff305026.png)

除了这两个规则之外，还可以根据自己的阅读习惯和场景，定义更多的规则，比如规则 C是总结段落，规则 D 是句子自动换行，规则 E 是替换或去除某些词，等等。

另外，还可以对规则进行组合，例如下面的prompt告诉ChatGPT，不同的规则是可以组合的，于是我们可以让它同时应用规则 A 和规则 B，在翻译部分单词的同时为术语加上emoji🤖️，如下图。同样的，还可以有规则 A + C，或是 规则 A+ B + D，等等。


![](https://files.mdnice.com/user/40454/0b702641-5518-45e5-a412-5b995776fd62.png)

不过，ChatGPT的记忆有限，如果定义了很多规则，它很快就会忘记，而且每次都要写指令告诉它应用什么规则，还要复制粘贴段落，目前这个方法还没有那么实用，等以后ChatGPT记忆容量提升时候，便会比较有用。

这其实可以通过设计更好的交互进行改善，想象一下，每当你打开一个英文网页的时候，浏览器便会根据你事先定好的规则，把这篇文章所有的段落都很根据你的规则进行转换，提供适合你的阅读体验。

这个示例就介绍到这里，想要进一步了解ChatGPT的对学习英语的帮助可以见: [如何用ChatGPT愉快地学英语](https://www.notion.so/ChatGPT-e33f901c938c496983fd06afa539afe7) ，更复杂的案例可以见 [教ChatGPT拆解复杂问题 ](https://www.notion.so/ChatGPT-10db8b2eeddc49fdb583da0fab327c4b) 和 [关于编程的编程](https://www.notion.so/fa19ea2606f54a47a2be928390d82ae4) 。

软件1.0和软件3.0有着很大的区别，一个使用精确的编程语言，一个使用模糊的自然语言，两者各有各的优点和缺陷。但如果我们可以结合两者呢？软件1.0 + 软件3.0 会等于什么？为了方便，我们暂且称之为 软件3.5吧。

# 2 软件3.5

当前存在许多的工具，能够将软件1.0和软件3.0进行结合，有给开发者使用的LangChain，也有一些更简单的零代码和低代码工具。

## 2.1 开发工具

其中一个是LangChain，[https://langchain.readthedocs.io/en/latest/getting_started/getting_started.html](https://langchain.readthedocs.io/en/latest/getting_started/getting_started.html)。这是一个开源的项目，开发者可以使用这个库，更好的利用语言模型。

例如：

1. GPT只能生成代码，不能运行，此时可以利用这个库，执行生成的代码；

2. 为了提高GPT回答问题的准确性，在GPT回答问题前，先去搜索引擎查找一下资料；

3. 如果要总结一篇很长的文章，直接扔到GPT放不下，这时可以将文章拆成一小段一小段，每一段用GPT生成简短的小结，最后将小结拼在一起，让GPT给出最后的总结。

下图展示了这样一个例子，在回答一个问题前，会先利用工具进行搜索，获得新信息，如果还不能解决问题，会再次进行搜索，最后涉及到了一个计算问题，于是调用了计算器进行计算。通过利用额外的工具，可以得到更准确的答案。

![](https://files.mdnice.com/user/40454/ced0b410-6e61-451d-8945-fb3fe891761b.png)


然而，正如我们前面提到的，软件3.0最大的好处，就是人人都可以使用，如果只能使用LangChain才能做出新一代的应用，由于用到了编程语言，就需要人们再去学习，成本比较高。要是能把这件事情的难度再降低就好了。

ChatGPT已经可以生成代码了，但它还不知道有LangChain的存在，因此没法利用。不过在不久的未来，ChatGPT学了新知识以后，人们就可以让它使用LangChain了，普通人可以不用懂软件1.0的代码，一切都交给ChatGPT。

另外，市面上已经有一些零代码或是低代码的工具来帮助人们利用GPT来制作一些简单的程序，比如Dust、Agent、brancher，当然还可以在iOS的捷径中使用。

*零代码的背后仍是软件1.0，但更用户友好，不过功能上比较有限。*

# 3 作为模拟器的ChatGPT

人们对设想中的AI进行了分类。（下图，[https://www.lesswrong.com/posts/vJFdjigzmcXMhNTsx/simulators](https://www.lesswrong.com/posts/vJFdjigzmcXMhNTsx/simulators)）
![](https://files.mdnice.com/user/40454/6cc1b462-31b0-462a-9189-bf3a7ea8d819.png)

这篇文章的作者，把ChatGPT当作了模拟器，它可以模拟很多东西，比如人、动物、网页、机器人、程序执行器…，可以模仿其它类别的AI，甚至还能模仿它自己。

例如，这个作者用GPT模拟了维基百科的页面，在用户输入关键词后，GPT将会生成一个解释该关键词的百科页面，GPT能做到这一点是因为它的训练数据中包含了互联网上很多的网站和内容，不过生成的页面中会存在很多不真实的信息，因为这只是在模拟。

**prompt-1**

```markdown
I want you to act like a Python interpreter.
I will give you Python code, and you will execute it.
Do not provide any explanations.
Do not respond with anything except the output of the code. 
The output should inside the code block.

The first code is: "print('hello world!')"
```

**输出-1**

```python
hello world!
```


![](https://files.mdnice.com/user/40454/79163aa5-626c-40df-9353-ec5eed2d207f.png)

注意：ChatGPT只是在模拟，它并不能真正的运行代码，如果你写的程序很复杂，它得到的结果很可能是错误的， 一个简单的测试方式是，让它做一道算术题。如下图，ChatGPT算出的答案是错误的，模拟其它事物，并不能让它获得原来没有的能力。

## 3.2 模拟gpt()的API（软件3.0）

接下来，在同一个对话下，我们让它模拟GPT，即模仿它本身的行为。

**prompt-2**

在这个prompt中，我们定义了一个API叫做gpt()，这个API可以输入一个prompt，并输出一个结果completion。

prompt提供了2个调用gpt()示例，供ChatGPT学习这个API是怎么运行的。

在prompt的最后，我们写了一个简单的Python代码，循环调用gpt()三次，每次让它生成一个随机的英文单词。

```markdown
There is a LLM API called gpt(), it take a prompt as input, and output the completion, prompt and completion are both string type.

Here are some examples when calling gpt():

completion = gpt("what is one plus one?") 
the completion will be: "2"

completion = gpt("translate to chinese: cat and dog are cute") 
the completion will be: "猫和狗很可爱"

the gpt() api works just like ChatGPT, so you can predict the output of this API.

Now, you are act like  Python interpreter. the second code is:

for i in range(3):
    completion = gpt("generate a random English word")
    print(completion)
```

**输出-2**

```python
calibrate
biochemical
remembers
```

![](https://files.mdnice.com/user/40454/adfd862d-7288-40a5-9c36-64b6fa39f6de.png)


到这里，我们事实上已经让ChatGPT模拟了软件3.5。

接着在同一对话下，我又输入了一段简单的prompt，目的是为了进一步测试ChatGPT的能力，以及产生更多的例子供它学习。

**prompt-3**

这个prompt中，先调用gpt()生成了一个笑话，接着再调用gpt()解释笑点在哪里，最后调用gpt()把笑点翻译成中文。

```markdown
joke = gpt("give me a joke")
print(joke)

explain = gpt(f"explain why this joke {joke} is funny?")
print(explain)

translation = gpt(f"translate to chinese: {explain}")
print(translation)
```

**输出-3**

```python
Why was the computer cold?
Because it left its Windows open.

The joke is funny because the phrase "left its windows open" is usually used when talking about leaving windows open in a physical sense, but in this case it is referring to the computer operating system "Windows."

这个笑话为什么好笑？ 
因为“left its windows open”这个短语通常用于指物理意义上的窗户没有关好，但在这个笑话中它指的是电脑操作系统Windows。
```

注意，在这里以及下面的示例中，写prompt时都会把让它把过程中的每一步都进行输出(print)，目的是让ChatGPT记住中间的步骤，如果直到最后才输出(print)，ChatGPT将很容易犯错。这是和实际编程不一样的地方。

## 4.1 实现递归的新方式

我在 [关于编程的编程](https://www.notion.so/fa19ea2606f54a47a2be928390d82ae4) 当中，设计了一个prompt，让ChatGPT学会如何递归，但设计这个递归，需要用到很多prompt的技巧，比较麻烦。现在，我们能够模拟软件3.5了，可以用代码来实现递归了。

例如，在下面的prompt中，我写了一个不断问问题的函数ask()，输入一个问题后，它将调用gpt()返回一个子问题，接着在这个函数内递归调用它自己ask()，即根据子问题，继续问出子子问题。


![](https://files.mdnice.com/user/40454/c8eb6f94-1fb9-44b2-8741-69836d2bc963.png)

于是，我们可以用这种方式，实现 [关于编程的编程](https://www.notion.so/fa19ea2606f54a47a2be928390d82ae4) 里面持续不断改进代码的prompt，如下图。

![](https://files.mdnice.com/user/40454/e3298239-119e-458e-98ae-7aaf2e920f76.png)

在prompt中定义了2个函数：
1. 一个是根据需求写出代码的函数writecode()，它会调用gpt()来写出第1个版本的代码；
2. 另一个是改进代码的函数improve()，它会调用gpt()将原来的代码进行更新，写出第2个版本的代码，然后它将进行递归，在它内部调用它自身，实现代码的不断改进。

在improve()的代码中，增加了一行注释，告诉ChatGPT这个代码不会无限递归，如果没有这个注释，ChatGPT将拒绝运行这段代码。这里我们再次看到，ChatGPT模拟软件3.5的方式，和实际编写软件3.5的方式相比，结果是很不一样的。

下面是这段prompt的输出，代码改进的效果并不好，甚至还会写出更糟糕的代码。
![](https://files.mdnice.com/user/40454/99e0e752-1859-4f5e-87d5-17d779276f5e.png)
这可能因为我的prompt写得太简单了，如果在改进代码前，先让ChatGPT分析代码存在的问题，并给出如何改进的建议，或许可以得到更好的结果，但也可能随着prompt的变复杂，得到更差的结果。在这里为了示例比较简单，我没有做进一步的尝试。

我尝试一些更复杂的场景，如编写很多个函数，同时还有递归，得到的结果不太好，ChatGPT目前还不能模仿复杂代码的运行。但是对于一些简单的递归还是可以的。

在ChatGPT写代码和实际的写代码是很不一样的，在这里最好告诉ChatGPT某一行的作用，并输出(print)每一个步骤，步骤间的逻辑也要比较清晰，否则ChatGPT将无法理解，得到的结果也会错漏百出。
